# bdesk 改造清单协作约定

> 适用对象：读取项目记忆目录（默认 `{{MEMORY_DIR}}/`）的所有 Agent（{{AGENT}}）。
> 本 skill 由 `bdesk skill` 安装；若项目记忆目录另有《改造清单协作约定.md》，**以该文件为准**（它由工作台维护、只读）。
> 执行要求速记：**单写点、不删行、不重排 ID、不手写镜像、不自动提交**。

## 0. 先定位本项目的清单

1. 读配置找：`~/.backlog-desk/config.json`（或仓库内 `config/workbench.json`）的 `projects[]`，按项目 id 取 `memoryRoot` 与对应 Agent 适配器的 `backlogFile`。
2. 或直接探测：`<项目根>/{{MEMORY_DIR}}/改造清单.md`。
3. 都没有：提示用户运行 `bdesk start`，在页面「添加项目」登记；**不要自行发明路径**。

## 1. 唯一权威源

记忆目录下 `改造清单.md` 中 `<!-- backlog:begin -->` 与 `<!-- backlog:end -->` 之间的 Markdown 表格，是改造清单的**唯一权威状态**。

- `MEMORY.md` 末尾的 `<!-- backlog-sync:begin/end -->` 状态镜像是工作台自动生成的，**不是权威源**。
- `YYYY-MM-DD.md` 日志中的历史清单描述仅为决策留痕（含降级、移除等当时的判断），**不得据此把已移除项重新列为待办**。
- 三处口径冲突时，一律以 `改造清单.md` 标记区块为准。

## 2. Agent 单写点（严格）

| 文件 / 区域 | 可写 | 说明 |
|---|---|---|
| `改造清单.md` 标记区块内 | ✅ **只允许这里** | 新增 / 改优先级 / 改状态 / 改文案 / 标记移除 |
| `MEMORY.md` 的镜像区块 | ❌ 禁止 | 由工作台幂等维护，手写会被下次同步覆盖 |
| `MEMORY.md` 其余部分 | ⚠️ 不建议写状态 | 可写决策背景，但不要写「当前待办 / 优先级」结论 |
| `YYYY-MM-DD.md` 日志 | ✅ 可 append | 只追加，不修改已有行；可记执行过程与决策依据 |
| 《改造清单协作约定.md》 | ❌ 禁止 | 只读契约，由工作台维护 |

## 3. 表格格式与枚举

列固定为 `id | priority | status | title | note | updated`，顺序不可变。

| 字段 | 取值 |
|---|---|
| `id` | 数字字符串，**新增取当前最大 id + 1**；删除不回收、不重排 |
| `priority` | `P0` / `P1` / `P2` / `P3` |
| `status` | `todo` 待办 / `doing` 进行中 / `done` 已完成 / `removed` 已移除 |
| `title` / `note` | 单元格内 `|` 写 `\|`，换行写 `<br>` |
| `updated` | `YYYY-MM-DD`（本地日期） |

示例行：

```markdown
| 12 | P0 | doing | 统一按钮语义 | 由工作台 2026-11-09 新增 | 2026-11-09 |
```

## 4. 增删改规则

- **新增**：在标记区块表格末行追加，不要动表头与分隔行。
- **删除**：把 `status` 改为 `removed`，**不要删行**；在 `note` 写清为何移除。物理删行会丢失决策依据，也可能让 ID 重排。
- **降级 / 升级**：只改 `priority`，`id` 保持不变。
- **完成**：只改 `status` 为 `done` 与 `updated`，不要删行。
- **改完不要手动同步镜像或日志**：工作台会自动感知并校准。

## 5. 工作台会自动做什么

1. 监听记忆目录的文件变化（去抖 500ms）。
2. Agent 直接改 `改造清单.md` → 追加一条 `source:agent` 事件到工作台 `history.jsonl`，并**自动幂等校准** `MEMORY.md` 状态镜像 + 当天日志追加一行。
3. 看板通过 SSE 自动刷新；若自动校准关闭或失败，看板显示「待校准」，需人工点「同步」。
4. 工作台写回前比对清单 `mtime`；若你正在改文件，编辑请求返回 409，刷新后重试即可。
5. 工作台写回不会改动镜像区块外的任何历史行，也不会删除日志已有内容。

## 6. 任务卡派发闭环（手动）

工作台**不会自动唤起 Agent，不会自动改代码 / commit / push**。

新增改造项或把状态改为 `doing` 时，看板生成一张 `pending` 任务卡（含项目路径、条目、执行要求），由维护者手动复制指令到 Agent 会话执行。Agent 收到任务卡后：

1. 先读记忆目录的《改造清单协作约定.md》（若有）与 `改造清单.md`。
2. 完成改造后，只把该行 `status` 改为 `done`、`updated` 改为今天（本地日期），不要删行、不要重排 ID。
3. 执行过程可在当天日志 append 一行留痕；**不要自动 commit / push**。
4. 闭环由工作台自动感知完成，无需手动同步。

## 7. bdesk 命令速查

| 命令 | 作用 |
|---|---|
| `bdesk`（无参） | 启动看板 `127.0.0.1:8787`，等价 `bdesk start` |
| `bdesk init` | 生成用户态配置 `~/.backlog-desk/config.json`（`--from FILE` 导入、`--force` 覆盖） |
| `bdesk doctor` | 体检：项目路径、清单文件、配置端口占用 |
| `bdesk demo` | 脱敏示例复制到临时目录启动（8788），不碰真实记忆 |
| `bdesk skill` | 安装本协作约定 skill：项目级 `{{SKILLS_DIR}}/bdesk-collab/`；`--global` 装用户级 `{{HOME_SKILLS_DIR}}/bdesk-collab/`；`--force` 覆盖 |
| `bdesk help` | 完整帮助（等价 `-h` / `--help`） |

完整字段含义与功能说明见包内 `README.md` 或 <https://github.com/huazie/backlog-desk>。
